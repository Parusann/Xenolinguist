## W21 proposal backend: first implementation unit

The authenticated read-only endpoint generates typed lexical, grammar and requested-observation proposals on a private profile snapshot. Profile-scoped retrieval includes source identities, annotations, linked hypotheses and counterevidence. Four bounded tools can inspect evidence and preview/test a candidate; they cannot write files or persistent knowledge. Server validation rejects fabricated references and preserves deterministic counterexamples. Structured output uses one repair attempt, a shared deadline, a declared token ceiling and a pinned local model digest. Successful responses return prompt/input hashes, retrieval payloads, typed tool traces and timing provenance.

Local source gates pass 371 unit tests (340 server/shared/engine/evaluation and 31 client), seven tooling tests, lint, type checks and desktop build. The 21 new tests include actual HTTP transport, persistence noninterference, cancellation and model-identity changes. A real default-model smoke identified and repaired Ollama's Unicode-regex schema incompatibility, then completed with two tools, three calls and no repair. This is synthetic integration evidence, not the planned quality comparison. Exact-revision CI evidence is recorded after the implementation commit.

W21 remains in progress. The next unit adds durable review records, decisions and revision-checked application, then integrates the workbench and relevant AI entry points. The held-out/current-prompting comparison and acceptance coverage remain required before W21 completion. See [research proposals](research-proposals.md) for the precise delivered boundary.
